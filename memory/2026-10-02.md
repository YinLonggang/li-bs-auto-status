## 完成事项

### 项目阶段抽屉新增模式（P0）

- `PhaseConfigDrawer` 支持 `onCreate`：`phaseEditor.openRecord()`（无参）即新增模式，标题"新增项目阶段"、副标题说明阶段 Key 语义（检查项库条目按 Key 落位，创建后不建议修改）；仅新增模式展示"阶段 Key"输入。
- 客户端校验全部先于写请求：Key 格式（`^[A-Za-z0-9_-]{1,64}$`）、与现有阶段 code 重复预检（文案与后端 400 一致"该项目下已存在相同阶段 Key「…」。"）、名称必填、计划起止必填；创建成功 `editor.accept(created, …)` 转入编辑模式。
- 阶段配置面板头部新增"新增阶段"主按钮（`canWrite` 且有选中项目时可用，位于"按默认模板补齐"之前）。
- 删除语义显性化：受保护阶段（模板默认或仍有检查项，`canDelete !== true`）不再只是隐藏删除按钮，新增说明区"该阶段暂不可删除"，指向"检查项迁移"工具或仅停用阶段；迁移/删除区仍按 `record`/`canDelete` 门禁。

### "项目模块配置"面板（P1，原"模块负责人配置"升级）

- 新增"本项目检查项"列：总数 + `启用 X · 停用 Y · 完成 Z` 实时统计。
- 每模块三个操作：负责人（原能力不变）、从库导入（复用 `LibraryEntryPickerDrawer`，`phaseKey=""` 显示全部阶段启用条目，多选后一次 `POST /projects/{id}/import-library-items/`）、退出项目（确认文案含影响范围"停用 N 个启用检查项，不删除任何数据"，确认后才发 `POST /projects/{id}/disable-module/`）。
- 结果消息（`role="status"`）汇总导入数量与逐条跳过原因；导入/退出进行中按钮级 busy 防重复点击；成功后 `loadData` 全量刷新，统计列即时更新。
- services 新增：`createProjectPhase`（POST 嵌套 phases 路由，goal 同步 description/metadata.notes）、`importLibraryItems`、`disableProjectModule`（响应字段蛇形/驼峰双兼容归一）。

### 实现

- `bsAutoStatusApi.ts`：新增 `ModuleReferenceCheckItem`/`ModuleReferences`/`MigrateModuleCheckItemsResult` 类型与 `fetchModuleReferences`（GET `/inspection-modules/{id}/references/`）、`migrateModuleCheckItems`（POST `/migrate-check-items/`，`itemIds` 缺省即全量）；unwrap 兼容裸对象响应。
- `InspectionModuleDrawer` 重做：打开即自查 references（不再用工作区 `data.checkItems` 的当前项目口径，`moduleDrawerCheckItemCount/moduleDrawerChecklistCount` 已删除）；引用清单按项目分组展示（阶段/状态/已停用/来源/仅可迁移徽章），说明文案明确"停用不解除引用"；迁移栏（目标模块下拉排除自身 + 迁移所选/迁移全部，均 window.confirm 门禁）；逐行删除仅 `canDelete` 项渲染；迁移/删除后自动 refetch，引用清零时删除按钮自动解锁；references 加载失败或未加载时删除按钮禁用（防误删）；只读用户可见清单但隐藏一切操作。

- 逐行删除走 App `handleDeleteModuleReferenceItem`（按 id 删除 + loadData，rethrow 供抽屉内联报错）；与既有 `handleDeleteCheckItem`（吞错，仅供 MatrixCellDrawer）区分。
